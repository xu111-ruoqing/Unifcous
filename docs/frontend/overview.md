# 前端开发情况总结

最后更新：2026-04-01

说明：当前仓库主名称为 `Unifocus-v1.2`。本文中出现的 `UniFocus` 默认按产品界面品牌理解。

## 1. 结论

当前前端已经从“只有一个可用管理页的 Next.js 单点页面”发展到“保留旧 Next 基线，同时新增一个并行的 Vite + three.js 机会星球前端入口”的状态。

和最先版本相比，前端的主要变化不是业务闭环已经完成，而是：

- 技术实现边界变宽了
- 界面表达力明显增强了
- 可运行性和可验证性提高了
- 但主前端路线还没有最终收敛

换句话说，前端已经从“能管理竞赛数据”走到了“开始形成产品界面风格”，但还没有走到“完整产品前端已经做完”。

## 2. 最先版本的前端情况

最先版本可以概括为：

- 目录只有 `unifocus/web/`
- 技术栈是 `Next.js 14 + React 18 + TypeScript + Ant Design`
- 真正落地的页面只有 `web/app/dashboard/competitions/page.tsx`
- 页面功能集中在竞赛信息管理：
  - 搜索
  - 筛选
  - 新增
  - 编辑
  - 删除
- 视觉层基本还是管理后台式表格页面，没有形成品牌风格
- 全局布局和全局样式仍有明显脚手架残留
- `lib/api/` 已经有一些封装，但大多数页面并不存在

这一阶段的前端本质上更像：

- “后端功能验证入口”
- 而不是“完整产品前端”

## 3. 当前版本的前端情况

当前前端已经分成两条线：

### 3.1 旧前端基线：`unifocus/web/`

这条线仍然保留，作用是：

- 继续承接最初的 Next.js 基线
- 保留现有竞赛管理页
- 保持和原有 API 封装、Next 路由结构兼容

当前状态：

- `lint` 已修通
- `build` 已修通
- 已存在 `/ -> /dashboard` 重定向
- `dashboard` 总览页已落地
- `dashboard/competitions` 已落地并接真实后端数据
- `dashboard/planet` 已落地并可访问
- 竞赛页的 `useEffect` 依赖问题已修复
- `401 -> /login` 的错误跳转已移除
- 侧边栏未实现项保持禁用，避免 404
- `planet` 对空数据的崩溃已修复

当前默认结论：

- `unifocus/web/` 不再只是“只有一个竞赛管理页”的旧状态
- 当前主工作对象是 `unifocus/web/` 的 Dashboard / Planet 链路

### 3.2 新前端实验入口：`unifocus/web-vite/`

这条线是当前新增的界面改造成果，作用是：

- 在不破坏旧 Next 基线的前提下，补一个新的前端实验场
- 技术栈扩展为 `React + Vite + JavaScript + three.js`
- 直接面向“机会星球”风格进行界面表达

当前已实现：

- `Dashboard / Planet` 双风格切换
- three.js 主视觉场景
- 主星、轨道、卫星节点、粒子星尘等视觉结构
- 基于现有图片参考和 PDF 首页气质的视觉融合
- 能读取后端竞赛接口与机会接口
- 接口异常时有回落数据，不会直接空白

其中最新一轮 P0 调整后：

- `Dashboard` 被收回到更轻量的“机会直接展示”界面
- `Planet` 被简化成“左侧介绍文案 + 右侧大场景”的结构
- 星球界面删除了大量浮层和次级信息块，强调主视觉占比

这一阶段的新前端已经具备：

- 更强的视觉识别度
- 更明确的产品方向表达
- 更适合继续扩展首页、机会页、画像页等产品化页面

## 4. 与最先版本的对比

### 4.1 技术栈对比

最先版本：

- `Next.js + React + TypeScript + Ant Design`
- 偏管理后台与 CRUD 页面

当前版本：

- 保留原 `Next.js` 前端
- 新增 `React + Vite + JavaScript + three.js`
- 前端技术边界从“表格式管理页”扩展到“沉浸式可视化界面”

### 4.2 页面形态对比

最先版本：

- 单一竞赛管理页
- 以表格、表单、弹窗为主

当前版本：

- 仍保留竞赛管理页
- 新增“机会星球”主界面
- `Dashboard` 更偏直接展示机会
- `Planet` 更偏品牌介绍和视觉展示
- 能在 `Dashboard` 和 `Planet` 两种视图之间切换

### 4.3 视觉表现对比

最先版本：

- 偏默认后台风格
- 品牌感和产品感较弱

当前版本：

- 已开始形成“机会星球”视觉语言
- 参考了仓库中的图片素材
- 吸收了 PDF 首页的深色封面气质
- three.js 场景带来了明显更强的空间感和记忆点

### 4.4 数据接入对比

最先版本：

- 主要接竞赛 CRUD
- 以 `/api/v1/competitions` 为主

当前版本：

- 新前端会尝试接：
  - `/api/v1/competitions`
  - `/api/v1/opportunities`
- 已具备把后端数据映射成轨道和节点的能力
- 但这还只是第一步，仍未覆盖完整业务闭环

### 4.5 工程状态对比

最先版本：

- 可运行，但前端边界非常窄
- 更偏“验证后端是否通”

当前版本：

- 可运行性更强
- 有两条可用前端线
- 已经能承接更强的产品设计改造
- 但也带来了新的工程问题：主前端到底选 `web` 还是 `web-vite`

## 5. 当前已经完成的前端成果

目前可以明确算“已经完成”的内容有：

- 旧 Next 前端竞赛管理页可运行
- 旧 Next 前端 `lint` / `build` 代码层已修通
- 旧 Next 前端 Dashboard 总览页已存在
- 旧 Next 前端 Planet 页面已存在并可访问
- 旧 Next 前端根路由已收口到 `/dashboard`
- 新 Vite 前端已经搭起
- 新 Vite 前端的机会星球主界面已经实现
- `Dashboard / Planet` 双风格切换已经实现
- `Dashboard` 已收敛为直接展示机会的轻量视图
- `Planet` 已收敛为左文案右大场景的展示视图
- three.js 基础场景已经接入
- 图片与 PDF 风格参考已经落实到界面里
- 新前端开发服务可启动
- 后端 API 已能为新前端提供基础数据

## 6. 当前还没有完成的部分

以下内容目前仍不能说“已经完成”：

- 登录页
- 登录态闭环
- 用户画像页
- 机会列表页
- 机会详情页
- 简历上传页
- 完整导航体系
- 新前端统一 API client
- 新旧前端的最终收口方案

也就是说：

当前完成的是“前端壳与视觉方向”

还没有完成的是“完整产品前端闭环”

## 7. 当前阶段的主要风险

当前前端最需要注意的不是“页面完全没有”，而是以下几个结构性问题：

- 同时存在 `web/` 和 `web-vite/` 两套前端，主线仍需持续收口
- Next 主线 Planet 的交互、视觉和数据映射仍需继续打磨
- 侧边栏仍有未开放项
- 统一鉴权、登录页和完整 API client 闭环还没有完全收口

这些问题不影响继续开发，但会影响后续是否能稳定演进。

## 8. 下一步建议

如果继续推进前端，建议按这个顺序：

1. 先继续完善 `unifocus/web/` 的 Planet 交互、视觉和数据映射
2. 再补登录与 API client
3. 再补机会列表、详情、画像等业务页面
4. 最后决定是否把 `web-vite/` 的成果继续迁移或长期保留

## 9. 一句话总结

最先版本的前端是“一个能用的竞赛管理页”，当前版本的前端已经升级成“保留旧管理页基线，同时拥有一个具备机会星球视觉方向的新前端入口”，前端成熟度明显提高，但还处在“产品化形成中”，不是最终完成态。
