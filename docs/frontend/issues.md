## 2. 需要优先整理的问题

### P0：当前前端主线的核心问题

1. Planet 交互还不够顺滑
   - 现状：页面已能打开，但交互节奏、聚焦反馈和信息切换仍有继续打磨空间。
   - 影响：当前 `planet` 更像“已跑通的视觉原型”，还不是最终可交付体验。
   - 当前状态：未完成，是后续第一优先级。

2. Planet 视觉仍可继续增强
   - 现状：已具备星球界面，但梦幻感、深空层次和主次关系还没有完全达到目标。
   - 影响：视觉记忆点已有基础，但还没有到“机会星球”理想表达。
   - 当前状态：未完成，是后续第一优先级。

3. 子星数量没有与后端更完整匹配
   - 现状：当前前端仍存在主动截断机会数量的逻辑。
   - 影响：显示出来的子星数量偏少，容易让用户误以为后端数据本来就不完整。
   - 当前状态：未完成，是后续第二优先级。

### P1：结构已存在但产品闭环缺失的问题

4. 主前端路线仍未完全收敛
   - 现状：现在同时存在 `web/` 和 `web-vite/` 两套前端入口。
   - 影响：后续如果继续扩页面，仍要持续避免双线持续分叉。
   - 当前判断：默认先沿 `web/` 推进，`web-vite/` 主要作视觉参考。

5. 登录页和完整鉴权闭环仍未完成
   - 现状：`401 -> /login` 的错误跳转已经清掉，但真正的登录页还没补齐。
   - 影响：现阶段只能避免错误跳转，不能算完整登录体系。

6. 置灰侧边栏项仍未落地
   - 现状：`机会列表`、`用户画像`、`简历上传`、`设置` 仍处于禁用状态。
   - 影响：导航结构已经显性存在，但业务页还没补齐。
   - 当前状态：可选推进，不应抢占 Planet 主任务。

### P2：体验与可维护性问题

7. 全局布局仍有脚手架残留
   - 位置：`web/app/layout.tsx`
   - 现状：标题仍是 `Next.js`，描述仍是 `Generated by Next.js`。
   - 影响：品牌信息、SEO、页面外壳都未成型。

8. 全局样式引用了未在文件中定义的 CSS 变量
   - 位置：`web/app/globals.css`
   - 变量：`--foreground-rgb`、`--background-start-rgb`、`--background-end-rgb`
   - 影响：样式依赖不完整，属于脚手架残留。

9. 前端依赖和真实使用范围不一致
   - 已安装但当前未见实际使用：`zustand`、`@tanstack/react-query`、`dayjs`、`recharts`

## 7. 2026-04-01 主前端修复批次经验

### 7.1 本轮暴露出来的真实问题

- 用户直接打开根路由时没有进入 Dashboard
- `planet` 页面触发运行时崩溃
- 某些情况下 Next 会报缺失 chunk，如 `Cannot find module './310.js'`
- 接口返回 `null` 时，前端直接按数组处理

### 7.2 已确认根因

- 根路由缺页
- `401` 错误跳到不存在的 `/login`
- 侧边栏死链接把用户带到未实现页面
- 多个 `next dev` 进程与混写产物导致 `.next` 损坏
- 数据层和展示层都缺少对 `null` 响应的防御

### 7.3 后续默认排查顺序

1. 先确认用户打开的真实地址
2. 再确认代码里真实存在的页面入口
3. 再确认是否存在鉴权跳转到不存在页面
4. 再确认本机是否有多个 Next 进程或损坏的 `.next` 产物
5. 再确认接口返回的数据形状
6. 最后再做重构、清理和去重

### 7.4 跨智能体交接最低要求

后续如果修到一半需要换人，至少要留：

1. 当前现象
2. 已确认根因
3. 已修改文件
4. 已验证通过的页面或命令
5. 还未解决的风险

详细总入口以根目录 `agent.md` 为准。
